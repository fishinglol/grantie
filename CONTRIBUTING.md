# Contributing a plugin

Plugins are listed in Granite's **Store** only after a maintainer has read their code. Nothing is installed from an
unreviewed source.

## How

1. Fork this repo.
2. Add or change a folder in `examples/plugins/<id>/` with `manifest.json`, `main.js` and a short `README.md`.
   Start from `examples/plugins/hello-granite`; the API is `packages/plugins/src/api.ts` (`GraniteApi`).
   Plain JavaScript that runs as it is: no build step, no minifying, no bundled libraries.
3. Run `npm test --workspace @granite/plugins` (checks the manifest and that the folder name equals the `id`).
4. Open a pull request and fill in the checklist.

The Store lists every folder in `examples/plugins/` automatically. The desktop Store is bundled into the app when it is
built, and the phone's list is generated by `npm run build:editor` in `apps/mobile`, so a merged plugin reaches users with the
next app release.

## Rules

- `id`: lower-case letters, digits and dashes, equal to the folder name, not used by another plugin.
- Raise `version` whenever `main.js` or the manifest changes, or users never see **Update**.
- Ask only for the `permissions` the plugin really uses, and say why in the README. The risky ones are `network`
  (data can leave the device), `vault.write`, `vault.read` and `editor.style` (CSS applies to the whole app).
- Show notes' text with `textContent`, never by building HTML from it.
- It must work on the phone as well as the desktop, or set `"desktopOnly": true`.

## What the reviewer checks

The automated test only checks the manifest's shape. The maintainer reads `main.js` in full and checks that:

- the permissions match what the code does (no `network` unless it needs it; no `vault.write` for a plugin that only reads),
- there is no `eval`, remote script, or use of note text as HTML,
- nothing is hidden: no minified or obfuscated code, no unexplained URLs,
- it does not loop forever (a stuck plugin freezes its own frame) or write to the note in a loop,
- the `id` and `version` follow the rules above.

Plugin authors keep the copyright to their plugin; by opening a pull request you agree to license it under this repo's
license (see `LICENSE`).
